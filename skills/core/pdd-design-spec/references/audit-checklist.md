# 界面规范审计清单（12 项）

> 生成 DESIGN.md 后必跑。也是前端 PR 的视觉一致性检查表。
> 每条都给出**判定方法**——能勾的勾，不能靠"看着还行"。

---

## A. 地基（front matter）

### 1. YAML 合法性

**判定**：能解析，且 `colors` / `typography` / `spacing` / `rounded` / `components` 五个顶层键存在。

```bash
node -e "
const fs=require('fs'),yaml=require('js-yaml');
const s=fs.readFileSync('ui/DESIGN.md','utf8');
const m=s.match(/^---\n([\s\S]*?)\n---/);
if(!m) throw new Error('无 front matter');
const t=yaml.load(m[1]);
['colors','typography','spacing','rounded','components'].forEach(k=>{
  if(!t[k]) throw new Error('缺少 '+k);
});
console.log('OK');
"
```

**常见错**：hex 没加引号（`primary: #165DFF` → YAML 会当注释）、缩进混用 tab。

### 2. 无裸 hex

**判定**：`components` 下所有值只能是 `{token.path}` 引用或非颜色字符串。

```bash
grep -nE ':\s*"#[0-9a-fA-F]{3,8}"' ui/DESIGN.md | grep -A0 'components' || echo "需人工确认 components 段"
```

更可靠的做法是跑 `token-spec.md` 第六节的脚本。

### 3. 引用完整性

**判定**：每个 `{colors.x}` / `{typography.x}` / `{rounded.x}` / `{spacing.x}` 引用的 token 都真实存在。

> 引用失效是最隐蔽的错误——写错一个字母，运行时静默回退到默认值，视觉上"只是有点不对"。

## B. 状态体系（最高优先级）

### 4. 状态覆盖完整

**判定**：DESIGN.md 中定义的状态数量 = PRD 功能需求 + spec 状态转换章节中出现的状态枚举数量。

**做法**：从 PRD 抓所有 `状态` 相关词，与 `state-*` token 逐个比对，列出差集。

**常见漏项**：定时发布、部分成功（多渠道路由）、已撤回、已过期、草稿被他人锁定。

### 5. 一色一义

**判定**：任意两个状态 token 的色相距离 ≥ 25°；品牌主色与任一状态色色相距离 ≥ 60°。

跑 `token-spec.md` 的色相检查脚本。

**典型冲突**：品牌主色是红色（政务/党媒常见），同时用红色表示"驳回"——此时按钮和驳回标签视觉同源，用户无法区分"这是操作"还是"这是状态"。

**修法**：品牌色改用深红/暗红并降低使用面积，或把"驳回"改为橙红 + ✕ 图标。

### 6. 双编码落实

**判定**：每个状态标签的 DOM 结构同时包含 ①颜色 ②图标或形状 ③文案。

```html
<!-- ✅ -->
<span class="status status--rejected"><i>✕</i>已驳回</span>
<!-- ❌ 只有颜色 -->
<span class="tag" style="background:#F53F3F"></span>
```

**抽检方法**：把页面截图转灰度，看状态是否仍可区分。

## C. 密度（后台必查）

### 7. 一屏行数达标

**判定**：在 **1366×768** 和 **1920×1080** 两个分辨率下实测，列表页净行数 ≥ 规范值（default 15 / compact 20）。

**方法**：浏览器窗口设为该尺寸，截图数行，不含表头和分页。

> 只测 1080p 是常见疏漏。政务、教育、医院内网大量是 1366×768。

### 8. 列数与操作列

**判定**：
- 最宽列表页列数 ≤ 10
- 操作列文字按钮 ≤ 3
- 操作列固定右侧（横向滚动时不动）

---

## D. 组件完整性

### 9. 组件状态闭环

**判定**：每个交互组件在规范中写全 8 态：rest / hover / active / focus / disabled / loading / error / 无权限。

**最容易漏的三个**：
- `loading`（提交中，按钮必须禁用 + 转圈，防重复提交）
- `error`（提交失败后按钮要恢复可用）
- **无权限**（隐藏？置灰？可见但点击提示？——必须三选一写死）

> 无权限态是后台系统的通病：A 模块隐藏、B 模块置灰、C 模块能点但报错。三种做法并存，用户永远不知道"是我没权限还是系统坏了"。

### 10. 空 / 错 / 加载三态

**判定**：规范中给出了三种场景的**文案模板**，不只是"显示空态图"。

| 场景 | 必须有的文案 |
|------|-------------|
| 首次无数据 | 说明 + 引导动作（"还没有稿件，去创建第一条"） |
| 筛选无结果 | 说明 + 清除筛选（"没有符合条件的稿件，清除筛选条件"） |
| 加载失败 | 原因 + 重试（"加载失败，网络超时，点击重试"） |

## E. 落地一致性

### 11. 组件库映射存在（RuoYi/Vue3 项目）

**判定**：§11 有 `--el-*` 变量覆盖块，且至少覆盖：primary / success / warning / danger / info / border-radius-base / font-size-base。

**为什么必要**：不覆盖 Element Plus 默认色，`el-tag type="success"` 会显示 Element 的绿而不是你的 `state-approved`，两套绿并存。

### 12. 间距与圆角落在刻度上

**判定**：代码中 `padding` / `margin` / `border-radius` 的值全部落在刻度内（4 的倍数，或明确的 2px 例外）。

```bash
# 抽查：找出非 4 倍数的 padding/margin
grep -rnoE '(padding|margin)[^:]*:\s*[0-9]+px' src/ | grep -vE ':\s*(0|2|4|8|12|16|20|24|32)px' | head -20
```

**常见漏网**：5px、10px、15px、18px、25px、30px——这些值几乎总是"手动微调"的产物，会让同类元素像素级不齐。
