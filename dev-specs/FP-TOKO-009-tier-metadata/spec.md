## 1. 接口定义

### 1.1 元数据扩展（唯一增量）

| 位置 | 新增字段 | 类型 | 必填 | 说明 |
|------|---------|------|------|------|
| `_meta.json` | `tier` | number(0-3) | 否 | 装配层级；缺省按 §2.2 目录类别推导 |
| `_meta.json` | `tokens_char` | number | 否 | SKILL.md 字符数自测回填（CAG 启动时自动补全） |
| SKILL.md front matter | `tier` / `tokens_char` | 同上 | 否 | 与 _meta.json 二选一即可；同时存在以 front matter 为准 |

### 1.2 兼容性约定（红线）

- 两个字段**全部可选**：任何技能不携带新字段时，现有消费方（lib/list.js、MCP、CLI、宿主路由）行为与 3.4.x 完全等价；
- 不改写既有 front matter 的其他键；不加 quote。

### 1.3 错误码

| 错误 | 触发 | 处理 |
|------|------|------|
| TIER_INVALID | tier ∉ {0,1,2,3} | WARN 并回退为类别推导值 |
| META_CONFLICT | _meta.json 与 front matter tier 不一致 | 以 front matter 为准，WARN 记录 |

## 2. 数据模型

### 2.1 缺省推导映射表

| 技能目录类别 | 缺省 tier | 说明 |
|-------------|----------|------|
| core | 1 | 核心流程技能，触发即装正文 |
| expert / pr / openspec | 1 | 同上 |
| entropy | 2 | 参考层为主 |
| 任意技能的 references/ | 2 | 参考层 |
| 运行时产物 | 3 | 工件层 |

### 2.2 枚举值定义

| 字段 | 值 | 含义 |
|------|-----|------|
| tier | 0/1/2/3 | 0=索引层描述（自动派生，无需标注）；1=正文；2=参考；3=工件 |

## 3. 业务逻辑

### 3.1 处理流程

1. 扫描 53 技能 → 2. 读取显式 tier（front matter 优先）→ 3. 缺省按 §2.2 推导 → 4. 回填 tokens_char → 5. 输出 tier 清单供 CAG（FP-TOKO-003）消费

### 3.2 业务规则

| 规则ID | 规则描述 | 约束类型 | 优先级 |
|--------|---------|---------|--------|
| R1 | 新字段缺省时行为与 3.4.x 等价 | 强制 | P0 |
| R2 | 53 技能全部有确定 tier（显式或推导），CAG 不处理无 tier 技能 | 强制 | P0 |
| R3 | 触发词与 description 不因本 FP 变化 | 强制 | P0 |

### 3.3 状态转换

无标注 → 推导 tier；显式标注 → 直接生效；冲突 → front matter 胜出 + WARN。
