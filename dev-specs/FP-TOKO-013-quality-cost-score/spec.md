## 1. 接口定义

### 1.1 扩展约定（对 lib/quality/scorer.js 的设计约束）

| 项 | 约定 |
|----|------|
| 接入方式 | scorer 输入新增**可选**字段 `cost`；类公开签名不变 |
| 开关 | 配置项 `quality.cost_scoring.enabled`，**默认 false** |
| 关闭语义 | 开关关闭时评分输出与 3.4.x **完全一致**（验收硬指标） |

### 1.2 cost 子项计算（开启时）

| 导出 | 说明 |
|------|------|
| `computeCostScore(records)` | 输入 FP-TOKO-002 消耗记录 → 输出 cost 子项分（0-100）：综合 token ROI + 缓存命中率加权 |

### 1.3 错误码

| 错误 | 触发 | 处理 |
|------|------|------|
| COST_DATA_MISSING | 开启开关但无消耗记录 | cost 子项记 null 并 WARN，不影响其余维度评分 |

## 2. 数据模型

### 2.1 cost 子项输入

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| tokens_total | number | 是 | 会话总消耗（估算/实测混合，标注 source） |
| cache_hit_ratio | number | 否 | 缓存命中占比（FP-TOKO-005 观测值） |
| phase | enum | 是 | 5 阶段 |

### 2.2 枚举值定义

| 字段 | 值 | 含义 |
|------|-----|------|
| enabled | true / false | 默认 false |

## 3. 业务逻辑

### 3.1 处理流程

1. 评分请求 → 2. 读开关 → 3. 关闭：走原评分路径（输出与 3.4.x 一致）→ 4. 开启：追加 cost 子项 → 5. 汇总分（权重配置化，默认 cost 权重 ≤0.1，避免质量让位于成本）

### 3.2 业务规则

| 规则ID | 规则描述 | 约束类型 | 优先级 |
|--------|---------|---------|--------|
| R1 | 开关默认关闭；关闭时评分逐字节一致 | 强制 | P0 |
| R2 | cost 子项只降总分不拦截交付（评分维度，非门控维度） | 强制 | P0 |
| R3 | cost 权重 ≤0.1 | 强制 | P1 |

### 3.3 状态转换

评分请求 →（enabled=false）原路径；→（enabled=true 且有数据）追加 cost 子项；→（enabled=true 无数据）cost=null + WARN。
