## 1. 接口定义

### 1.1 模块导出（设计约定）

| 导出 | 类型 | 说明 |
|------|------|------|
| `getAssemblyOrder(phase)` | 函数 | 返回规范装配顺序（区块序列） |
| `auditOrder(plan)` | 函数 | 对装配计划做稳定化审计，输出违规清单 |
| `stability-audit` 报告 | 产物 | 装配顺序审计清单（docs/reviews/ 惯例） |

### 1.2 规范装配顺序（强制）

```
[系统提示] → [Tier 0 索引（会话内不变）] → [Tier 1 已触发技能（只增不改）]
→ [对话历史] → [Tier 2/3 按需内容（放最末，随任务变化）]
```

### 1.3 错误码

| 错误 | 触发 | 处理 |
|------|------|------|
| ORDER_VIOLATION | 装配计划违反区块顺序 | 审计报告标记 CRITICAL，装配计划退回 CAG 重排 |
| VOLATILE_CONTENT | Tier 0/1 区块检出易变内容（时间戳/随机 id 等） | 审计报告标记 HIGH，要求移至尾部区块 |

## 2. 数据模型

### 2.1 区块顺序表

| 序 | 区块 | 稳定性要求 |
|----|------|-----------|
| 1 | 系统提示 | 会话内逐字节不变 |
| 2 | Tier 0 索引 | 会话内逐字节不变 |
| 3 | Tier 1 已触发技能 | 只增不改（追加不重写） |
| 4 | 对话历史 | 自然追加 |
| 5 | Tier 2/3 按需内容 | 允许变化，必须位于末尾 |

### 2.2 枚举值定义

| 字段 | 值 | 含义 |
|------|-----|------|
| severity | CRITICAL / HIGH | 顺序违规 / 易变内容混入稳定区 |

## 3. 业务逻辑

### 3.1 处理流程

1. CAG 产出装配计划 → 2. auditOrder 按 §1.2 顺序表逐块校验 → 3. 扫描 Tier 0/1 内易变内容（时间戳/uuid/随机序）→ 4. 违规退回重排 → 5. 通过后放行装配 → 6. 运行期观测缓存命中（cache read/write 用量比）

### 3.2 业务规则

| 规则ID | 规则描述 | 约束类型 | 优先级 |
|--------|---------|---------|--------|
| R1 | Tier 0/1 区块禁止插入时间戳、随机 id 等易变内容 | 强制 | P0 |
| R2 | 技能一旦装配，会话内不回溯移除 | 强制 | P0 |
| R3 | Tier 3 工件一律置尾 | 强制 | P0 |
| R4 | 目标：长会话缓存命中部分以供应商折扣价计费（OpenAI≈1/2、Anthropic≈1/10、DeepSeek≈1/10），综合节省 30–60% | 目标值 | P1 |

### 3.3 状态转换

装配计划草案 → 审计通过 → 放行；审计失败（ORDER_VIOLATION/VOLATILE_CONTENT）→ 退回 CAG 重排 → 再审计。
