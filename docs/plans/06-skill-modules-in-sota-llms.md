# 技能模块在 SOTA 大模型中的角色与未来发展方向分析

> 版本：v1.0 | 日期：2026-11-24 | 状态：分析报告（结论已出，供决策参考）
> 性质：战略分析文档，不改任何源码
> 分析对象：SKILL.md 类"技能模块"（prompt/上下文型程序性资产），非模型内部 expert/LoRA 模块
> 关联文档：[03-token-cost-optimization.md](03-token-cost-optimization.md)、[05-token-optimization-and-streaming-model-adaptation.md](05-token-optimization-and-streaming-model-adaptation.md)

## 0. 摘要（结论先行）

**待检验假设**："随着基座模型原生能力足够强，技能模块将边缘化，额外技能集成不再带来有意义的性能提升。"

**检验结论**：
- **强形式（技能整体边缘化）：被证伪。** 2024 之后的三条独立证据链——前沿实验室的产品行为、训练侧投入、基准测试的脚手架效应——一致指向技能层价值随模型变强而**上升**而非下降。
- **弱形式（部分技能贬值）：成立。** "知识注入型"技能（库用法、思维链话术、人设模板）正在被基座能力吸收，该类技能的市场持续萎缩。
- **修正后的命题**：基座模型越强，技能的**可执行上限越高、单条技能的半衰期越短、结构性价值越集中**。技能系统不是在退化，而是在经历"从知识容器到程序性资产"的范式迁移。

一句话：**强者淘汰的是"提示词技巧"，放大的是"工程化流程"。**

## 1. 假设检验方法论

### 1.1 假设的两种解读

| 解读 | 陈述 | 可证伪性 |
|---|---|---|
| **强形式** | 技能模块整体将边缘化——无论何种技能，集成后都无有意义的提升 | 可证伪：只需找到一类"集成后仍有稳定显著提升"的技能即可推翻 |
| **弱形式** | 存在一部分技能正在被基座能力吸收而失效 | 可验证：逐类追踪"有技能 vs 无技能"的消融差值随模型版本的衰减 |

### 1.2 检验标准

1. **产品证据**：前沿实验室（有能力做任何技术路线选择的主体）是否在 2024 后继续加码技能类产品；
2. **训练证据**：模型的训练管线是否在向"使用技能/工具"方向投入，还是相反；
3. **基准证据**：同一基座模型、不同技能/脚手架配置下的实测差值（消融实验）；
4. **经济学证据**：技能是否解决基座能力之外的约束（token 计费、缓存、确定性、组织治理）；
5. **反向证据**：哪些技能类别确实消失了（吸收现象的直接观察）。

## 2. 实证证据（post-2024）

### 2.1 反驳强形式的四条证据链

**证据链 A：产品行为——前沿实验室在"模型最强"的时点加码技能**

| 事实 | 时间 | 含义 |
|---|---|---|
| Anthropic 发布 **Agent Skills**（SKILL.md 格式、渐进式披露三层设计：name+description 常驻 → 正文按需 → 脚本/文件按需） | 2025-10 | 假设预测技能应边缘化；事实是最强模型厂商将其升为一等公民产品 |
| **MCP**（Model Context Protocol）从 Anthropic 单家提案发展为 OpenAI、Google、主流 IDE/Agent 全行业采纳的事实标准 | 2024-11 起 | 行业共识：模型必须与外部能力/流程体系结合，且需要**标准化协议**——"集成"本身在升值 |
| Claude Code / Cursor / Trae 等 Agent 产品均以持久化上下文文件（CLAUDE.md、rules、技能库）为核心设计 | 2025 全年 | 生产级 Agent 的第一设计要素就是"结构化上下文资产"，而非裸模型调用 |
| OpenAI GPTs/Apps/Actions 持续演进为面向消费者的技能容器 | 2024–2025 | To C 侧同样收敛于"模型 + 可插拔能力单元" |

> 关键点：这些主体完全有技术能力选择"把一切做进基座"，但产品决策相反。**技能是模型厂商主动让渡给用户的那部分可进化接口**——因为组织私有流程永远无法进入预训练数据。

**证据链 B：训练侧——模型训练正在把"会用工具/流程"作为目标，而非消灭工具**

| 事实 | 来源 | 含义 |
|---|---|---|
| DeepSeek-R1 / OpenAI o 系列将**推理能力**训练进权重（RL 驱动） | 2025-01 / 2024-09 | 确实吸收了一类"技能"（CoT 话术）——但注意：吸收的是 prompt 技巧，不是流程资产 |
| Kimi K2 技术报告：后训练阶段构造**数千条工具调用轨迹**（AgentScope 等），明确以"agent 能力"为训练目标 | 2025-07 | 模型侧在训练"更善于执行外部流程"，而非"摆脱外部流程" |
| GLM-4.5 / Qwen3 等国产旗舰公开的 agentic 训练叙事 | 2025 | 同上：工具/流程使用是训练目标的一部分 |

> 关键点：训练侧与技能侧是**共生关系**——模型被训练成更好的"技能执行器"，这降低了技能的编写成本、提高了技能的执行保真度，扩大了技能系统可表达的复杂度上限。

**证据链 C：基准测试——同一基座，不同脚手架，差值巨大**

- **SWE-bench Verified** 实践中，同一 Claude/GPT 模型在不同 Agent 脚手架（SWE-agent、OpenHands、Claude Code 及各团队自研 harness）下的得分差异长期维持在 **10–20+ 个百分点**量级；Terminal-Bench、OSWorld 等 agentic 基准同样呈现"基座固定、成绩随流程设计浮动"的模式。
- 差值来源正是技能层的构成要素：流程编排、验证回路、上下文装配、失败恢复策略。
- **这直接证伪强假设**：若基座原生能力足以覆盖，同模型不同脚手架应收敛到相同分数。事实是分数不收敛。

**证据链 D：经济学与组织约束——基座能力之外的问题依然存在**

即使假设基座"无所不知"，以下约束**不随模型能力改善而消失**：

| 约束 | 说明 | 技能模块的角色 |
|---|---|---|
| **Token 计费与前缀缓存经济学** | Anthropic/OpenAI/DeepSeek 对缓存命中部分给 50%–90% 折扣；上下文结构直接决定成本 | 结构化、前缀稳定的技能资产是吃满缓存折扣的载体（本仓库 doc 05 的设计依据） |
| **确定性/可审计** | 生产流程需要可重复、可审计的步骤与门禁，LLM 采样本质随机 | 技能承载流程门控（本仓库 4 级质量门控即实例） |
| **组织私有知识** | 公司内部规范、历史决策、领域流程**不在公共训练分布中**，永远不会被基座"原生知道" | 技能是组织程序性记忆的唯一注入通道 |
| **多模型/多供应商治理** | 生产系统需要跨模型可移植，避免锁定单家 | 技能层是供应商中立的可迁移资产 |

### 2.2 支持弱形式的证据（能力吸收确实在发生）

| 被吸收的技能类别 | 观察 | 判定 |
|---|---|---|
| CoT 话术类（"让我们一步步思考"） | o 系列/R1 之后成为多余，甚至干扰专用推理通道 | **已被吸收** |
| 人设模板类（"你是 20 年经验的专家"） | 增益归零到个位数，且随模型加强持续衰减 | **基本被吸收** |
| 公共库用法知识类（"Spring Boot 最佳实践""RuoYi 目录结构"） | 基座对主流框架的覆盖逐年加深；纯知识罗列型技能的边际增益递减 | **持续吸收中** |
| 单次性提示词微调（few-shot 范例堆砌） | 长上下文 + 强泛化使小样本堆砌性价比下降 | **部分吸收** |

> 这张表是弱假设的全部真实部分。注意其共同特征：**被吸收的都是"关于如何使用的公开知识"，吸收不了的是"私有流程 + 流程中的验证与治理"**。

### 2.3 检验结论

**强形式证伪**（证据链 A/B/C/D 独立且同向）；**弱形式成立**（2.2 表）。

修正后的行业命题（本文后续分析的公理）：

> **技能的价值不来自"补模型不会"，而来自"把模型会的事情变成组织内可重复、可审计、可计量的生产过程"。基座每变强一次，这个转换的性价比就上升一次；同时，纯知识型技能的半衰期就缩短一次。**

## 3. 能力吸收框架：技能价值的二维判定

用"私有性 × 程序性"给技能分类，可预测其在 SOTA 演进下的命运：

```
                 程序性弱（陈述知识）
                        │
   【正在贬值区】        │        【持续贬值区】
   人设模板/CoT话术      │   公共库用法罗列
   （已被吸收）          │   （吸收中，勿新增投入）
                        │
 私有性弱 ──────────────┼────────────────── 私有性强
                        │
   【结构性价值区】      │        【不可替代区】
   验证回路/门控/        │   组织私有流程
   上下文装配策略        │   （代码规范、领域流程、
   （基座越强越有用）    │    合规红线——吸收不了）
                        │
                 程序性强（可执行流程）
```

**推论**：
1. 技能系统的资源应从左上象限持续迁移到右下象限；
2. 每个技能应能被放入该矩阵并声明自己的位置（本仓库 `_meta.json` 可承载此元数据）；
3. **吸收检测**应成为技能生命周期的一等公民（见 §5.4）。

## 4. 技能模块仍须满足的关键功能需求

即便基座模型持续变强，以下六项需求**结构性地**无法被基座吸收（第 4.1–4.6 节按"为何基座无法替代"的逻辑展开）：

| # | 需求 | 为何基座吸收不了 | 生产实例 |
|---|---|---|---|
| 4.1 | **组织程序性记忆注入** | 私有流程不在公共训练分布；且组织流程持续演化，静态权重无法跟随 | 本仓库 expert-ruoyi 系列：若依 + 企业私有规范 |
| 4.2 | **上下文经济学管理** | 计费与缓存折扣是供应商经济学，与模型能力无关；同等能力下成本仍差数倍 | doc 05 的 Tier 装配 + 前缀稳定化设计 |
| 4.3 | **过程确定性与质量门控** | 采样随机性是原理性的；生产需要"每轮必过同一道门" | 本仓库 4 级门控 + PRD 30 规则 |
| 4.4 | **工具/子系统的编排策略** | MCP 给了模型"手"，但"何时用哪只手、按什么顺序、失败怎么恢复"是流程知识 | 契约发现→生成→验证→审计的 7-Phase 编排 |
| 4.5 | **行为红线与合规约束** | 模型对齐服务于通用安全，组织红线（行业合规、内部审计）必须显式注入 | 安全审计技能中的负面清单模式 |
| 4.6 | **能力落差的反事实兜底** | 团队实际部署的是多档模型混部（成本原因）；技能需在弱档模型上"抬下限" | 同一技能在 GLM-4.x 与旗舰档上的分级表达 |

## 5. 优先研发方向（可执行清单）

> 排序原则：先做"决定技能系统生死"的（5.1/5.2/5.4），再做"放大价值"的（5.3/5.5–5.7）。

### 5.1 上下文经济学型技能系统（Token-Economical Skills）

- **做什么**：把技能从"内容资产"升级为"装配策略资产"——tier 化、渐进披露、前缀稳定化、按阶段白名单装配。
- **为什么现在**：三家主流供应商的缓存折扣（50%–90%）使上下文结构直接等于成本；这是唯一一项"模型再强也不会消失"的工程杠杆。
- **落地锚点**：即本仓库 doc 05 的 CAG/PSE 设计；业界对应 Anthropic Skills 的渐进披露规范。

### 5.2 程序性资产化（Skills as Procedural Assets）

- **做什么**：技能编写范式从"教模型知识"迁移到"定义目标 + 验收标准 + 失败恢复"——面向推理模型只需给目标与约束，不再手把手写思维链。
- **范式变更**：老范式（步骤级指令）→ 新范式（`目标 / 约束 / 验收标准 / 红线 / 异常处理` 五要素声明式技能）。
- **落地锚点**：本仓库技能改造时的模板迁移；`pdd-verify-feature` 类"验收定义者"技能价值上升。

### 5.3 技能获取自动化（Skill Mining from Trajectories）

- **做什么**：从 Agent 执行轨迹中自动沉淀技能——识别"成功模式"并蒸馏为 SKILL.md 候选，人审后入库。
- **学术脉络**：Voyager（2023，技能库先驱）→ 2024–2025 各类 agent memory / 经验沉淀工作（MemGPT/Letta、A-MEM 一系）→ 生产化仍在早期，属高价值洼地。
- **落地锚点**：本仓库可从 `pdd-implement-feature` 高分执行记录中挖掘候选技能（entropy-reduction 技能群是天然的入库口）。

### 5.4 吸收检测与技能生命周期管理（Absorption Detection）

- **做什么**：为每个技能建立"无技能基线消融"回归——新模型版本发布时重跑，差值跌破阈值即触发**降级/退役**评审。
- **为什么关键**：这是把 §3 吸收矩阵变成可运维机制的唯一手段；也是技能系统长期公信力的来源（防止技能库腐化为"咒语合集"）。
- **量化定义**：技能 ROI = (有技能产出分 − 无技能产出分) / 有技能 token 成本；ROI 连续两个模型版本下降低于阈值 → 退役。
- **落地锚点**：本仓库 `scripts/token-analyzer.js` + 质量评分器已有全部原材料，缺的只是消融调度。

### 5.5 面向推理模型的技能形态迁移

- **做什么**：区分"推理敏感型技能"（必须改写为声明式）与"执行敏感型技能"（保持流程级）；为推理通道（thinking/reasoning）预留技能侧的"不要复述、直接执行"指令位。
- **落地锚点**：doc 05 §4.3 的 `reasoning_delta` 事件通道已在协议层预留了此能力。

### 5.6 技能即工具编排策略（Skills as Policy over Tools）

- **做什么**：技能不再自含工具用法说明，而是声明对 MCP 工具集的**编排策略**（前置条件、调用序、失败回退），与工具实现解耦。
- **为什么**：工具实现随供应商漂移，策略层稳定；这使技能天然可移植（doc 05 MSSA 的插件化思路同源）。

### 5.7 评测驱动的技能回归门控

- **做什么**：每个技能附带最小评测集（3–5 条断言级用例），技能变更 = 跑评测；技能库整体 = 一个 CI 可跑的回归套件。
- **落地锚点**：本仓库 4 级门控天然可扩展第 5 级"技能自检"；`pdd-code-reviewer` 是现成执行器。

### 5.8 多智能体技能分工（优先级最低，观察项）

- **做什么**：技能声明可并行的边界，供多 Agent 编排消费。当前主流生产实践仍以单 Agent 为主，此方向保持跟踪即可。

## 7. 成功判据：什么样的技能系统适配 SOTA 时代

一个技能系统设计是否合格，用以下八条判据（按可验证性排序）：

| # | 判据 | 通过标准 | 验证方法 |
|---|---|---|---|
| C1 | **消融增益可复现** | 核心技能在当前 SOTA 模型上的"有/无技能"消融差 ≥ 显著阈值（任务基准分或人工盲评） | 双臂 A/B 回归（§5.4 机制） |
| C2 | **吸收敏感** | 系统能在新模型版本发布后 N 周内产出技能贬值清单 | 吸收检测调度的存在与执行记录 |
| C3 | **Token ROI 为正** | 每技能的（增益 / token 成本）优于其消融基线；整库装配后单会话成本 ≤ 无技能自由发挥的等产出成本 | token-analyzer 报告 |
| C4 | **前缀稳定可缓存** | 技能装配满足 KV-cache 友好顺序；长会话缓存命中率有观测值且持续提升 | 供应商 cache read/write 用量比 |
| C5 | **声明式适配推理模型** | 核心技能无步骤级 CoT 话术残留；在推理模型上执行保真度不降 | 技能文本审计 + 双模型档位执行测试 |
| C6 | **跨模型可移植** | 同一技能在 ≥2 家族模型上通过其验收用例（差值容许 ≥10%） | 家族矩阵回归（doc 05 §5.2 的矩阵） |
| C7 | **组织资产闭环** | 私有流程改动 → 技能更新 → 验证生效，全链路 <1 天且有审计记录 | 技能变更走 git + 门控的轨迹 |
| C8 | **弱档兜底** | 技能在低档模型上产出分不低于无技能基线（技能不得"负优化"） | 多档模型回归 |

**直觉版总结**：合格的技能系统 = **有增益（C1）、知进退（C2）、省成本（C3/C4）、跟得上（C5/C6）、属于组织（C7）、不帮倒忙（C8）**。

## 8. 结论

1. **"技能模块将边缘化"的强假设被 2024 后的产品、训练、基准、经济学四条证据链一致证伪**；相反，Claude Agent Skills、MCP 标准化、agentic 训练投入都发生在模型最强的时点。
2. **弱假设成立**：知识注入型、话术型技能正在被吸收，半衰期以模型版本为单位计算。技能系统必须建立吸收检测与退役机制，否则会腐化。
3. **技能的本质正从"补能力"迁移为"管过程"**：组织程序性记忆、上下文经济学、确定性门控、工具编排策略——四者皆是基座能力之外的独立维度，模型再强也不消失。
4. **对本仓库的直接指引**：doc 05（上下文经济学）是对的方向且优先级最高；下一步应补"吸收检测"机制（§5.4），让 53 技能库成为有新陈代谢的活系统而非静态咒语集。
