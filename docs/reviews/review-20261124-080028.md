## 二、分维度发现（按严重级）

### High（2 项）

**H1. "REST 18 端点"与实际不符（事实错误，且落在兼容红线与验收承诺上）**
- 位置：05:L24（红线 3）、05:L348（§4.6 表）、05:L363（§5.1 承诺"REST 18 端点请求/响应 字节级不变"）
- 问题：`lib/api-routes.js` 实际注册 **17** 个端点（3 基础 + 2 规格 + 2 生成 + 2 验证 + 2 报告 + 3 配置 + 3 技能）。文档在三处反复使用"18"，其中 §5.1 直接将其作为契约快照测试的基线数量。
- 依据：见"事实核验速览"#5。
- 修改建议：三处统一改为 17；并在 §5.1 补一句"端点数以 `lib/api-routes.js` 数组为准，T0 基线标定时快照锁定"，避免未来端点增减时文档再次漂移。

**H2. 06 成功判据 C6 容差符号反向，按字面无法通过验收**
- 位置：06:L221（C6 行："在 ≥2 家族模型上通过其验收用例（差值容许 ≥10%）"）
- 问题："差值容许 ≥10%"语义为"差异至少 10% 才算可移植"，与"跨模型可移植"的意图相反；应为"差值容许 **≤**10%"。
- 依据：同表 C1–C8 均为"达标型"判据，C6 是唯一"差异越大越通过"的反常条目；05 §5.2 配套矩阵的校准误差口径也是 ≤5%，方向一致为小差值。
- 修改建议：改为"差值容许 ≤10%"，或明确写"各家族执行分差 ≤10% 视为通过"。

### Medium（5 项）

**M1. 05 沿用的 token 基线（13,700 / 201,500）来自 doc 03 的 48 技能时代，与 05 自述 53 技能口径混用且未声明**
- 位置：05:L16（§0.1 现状证据）、05:L135（Tier 0 估算"-49%"）、05:L259（收益总账）
- 问题：doc 03 明确其分析基础为"48 个技能"（03:L5, L15）。05 在声明 53 技能的同一段落引用 48 技能时代的基线数字，-49%（7,000/13,700）的算术成立，但分母已过期；若按 53 技能重测，当前 description 合计大概率高于 13,700，收益比例与绝对值都会变。
- 修改建议：二选一——（a）注明"基线沿用 doc 03（48 技能口径），T0 标定时重测 53 技能基线并回写"；（b）直接给出 53 技能的新基线。推荐（a），与 §6 T0"现状基线报告"任务自然衔接。

**M2. 05 §3.5"单会话综合 ≥40%"缺推算口径，不可复核**
- 位置：05:L255–L264
- 问题：表中各项措施作用于不同分母（固定开销 / Tier1 装配量 / 单报告 / 命中部分计费），直接并列后给出"≥40%（长会话 ≥55%）"，未说明合成方式（加权？连乘？场景假设？）。"与 doc 03 Layer 优化叠加后保守取值"不是推算过程。
- 修改建议：补一个典型会话场景的算例（如"IMPL 阶段 RuoYi 工程、10 轮会话、Anthropic 计费"），列出各措施的覆盖范围与合成公式；或明确标注"该数字为目标值而非推算值，以 T0 基线为准"。

**M3. 06 弱形式结论依赖的关键证据在附录中仅"中"置信，与附录自定的使用规约冲突**
- 位置：06:L88–L93（§2.2 弱形式证据表）vs 06:L249（"人设/CoT 话术增益衰减 | 中"）、06:L252（"中置信证据仅用于量级佐证，不承载结论"）

- 修改建议：二选一——（a）将弱形式结论措辞降级为"弱形式大概率成立（部分证据为中置信）"；（b）补充高置信来源（如官方提示工程指南的明确弃用声明）或将受影响行从"承载结论"改述为"量级佐证"。
