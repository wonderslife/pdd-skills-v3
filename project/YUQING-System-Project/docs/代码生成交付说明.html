2. 技术选型与架构

舆情数据的核心特征是写入量大、查询维度多、冷热分层明显。全量明细若与配置态数据同库，会迅速拖垮 MySQL。因此按「配置态 / 事实态」拆分双库：

层选型承担的数据理由
配置/状态库 MySQL 8 + MyBatis-Plus 22 张：任务、关键词、渠道、规则、模板、用户态、报告台账等 强事务、频繁更新、数据量小（万级）
事实/分析库 Apache Doris（Unique Key + Merge-on-Write） 7 张：yq_opinion、yq_collect_log、yq_opinion_analysis、yq_opinion_tag、yq_opinion_cluster、yq_opinion_metric、yq_stats_daily 亿级明细、按 collect_date 分区、中文倒排索引、聚合查询毫秒级；用 Stream Load 批量写入，无需 Kafka
应用层 Spring Boot 3 + Sa-Token + dynamic-datasource REST API，PC 与 H5 共用 v6 体系一致；@DS("doris") 做数据源路由，业务侧对 Doris 只读
PC 前端 Vue3 + TypeScript + Element Plus + Pinia 管理端（任务、关键词、渠道、模板、知识库） 复用 plus-ui v6 组件与 v-hasPermi 权限指令
移动端 RuoYi-App-Plus（uni-app，vue3 setup） 企业微信自建应用内嵌 H5 一套代码产出 H5；与 PC 共用账号体系与后端接口

2.1 双库路由的关键约束

dynamic-datasource 是按调用栈路由的。在 @DS("doris") 的方法里再去调 MySQL 的 Mapper，整个调用链都会打到 Doris 上，必然报表不存在。因此生成器对 Doris 表不生成关联名称回填逻辑，只留 TODO 注释： 
// TODO 关联名称回填：本表在 Doris，按 PRD §6.3 需由 master 数据源的 ExtService 批量补
正确做法是在 master 数据源里先查 MySQL 维表，再把结果传进 Doris 查询层。

2.2 Doris 建表约定

  • Unique Key：明细表统一 Unique Key(collect_date, url_hash) + Merge-on-Write，url_hash 为链接 SHA-256，天然幂等去重。
  • 动态分区：按 collect_date 日分区，起始 -1095 天、结束 +3 天。
  • 分桶：DISTRIBUTED BY HASH(url_hash) BUCKETS 16，replication_num=3。
  • 中文检索：title / content 建倒排索引（parser=chinese），支撑标题正文关键词检索。
  • 写入：Worker 通过 HTTP Stream Load 批量导入，单批 5000～20000 条，失败自动重试。

3.3 主子表（任务 → 关键词 + 渠道）

生成器对 YqTask 做了 master-detail 展开，这是接口一次讲清的关键：

  • 查询：列表/详情自动带出 keywordList / channelList；
  • 新增：先插主表拿雪花 ID，再逐条 setPk(null) 后插明细（防止主键冲突）；
  • 修改：明细先删后插（全量覆盖语义）；
  • 删除：级联删 taskKeywordMapper 与 taskChannelMapper，整体 @Transactional。
易错点（已在生成器中固化）：Mapper 的类型名必须用实体名（YqTaskKeywordMapper），只有变量名才用短键（taskKeywordMapper）。写成 import …mapper.taskKeywordMapper; 会直接编译失败。

7. 安全要点

7.1 SQL 注入

  • 全量使用 MyBatis-Plus LambdaQueryWrapper / 参数占位符，无字符串拼接 SQL；生成器不产出 ${} 占位。
  • 导出、下拉选项（optionselect）同样走 Wrapper，避免排序字段注入。
  • Doris 侧查询参数化传参，倒排索引检索用绑定变量。
  • 生产环境建议开启 MyBatis 日志脱敏与慢 SQL 监控。

7.2 XSS

最大风险点在报告预览。报告正文由大模型/模板渲染产出，属于不可信内容。H5 report/preview.vue 采用白名单净化后才交给 <rich-text> 渲染： 
1) 剔除危险标签：script / style / iframe / object / embed / link / meta / base / form
2) 移除全部 on* 内联事件属性（onclick、onerror…）
3) 拦截 javascript: / vbscript: / data: 协议
4) 清除 srcdoc 与 CSS expression()
  • 舆情详情页正文以纯文本 <text> 渲染，从根上避免 HTML 注入。
  • PC 端表格列沿用 Element Plus 默认转义，不使用 v-html。
  • 链接跳转（原文链接）统一走 window.open，不在同源内执行。
  • 后端建议对 title / content 在入库前做一次 HTML 转义兜底，形成双保险。

7.3 越权与鉴权

  • 所有写操作 Controller 均标注 @SaCheckPermission("yuqing:xxx:add|edit|remove")，与 yq_menu.sql 中 63 个按钮权限一一闭环（校验脚本已实测 20 个页面权限全部覆盖）。
  • 用户身份只从会话取：LoginHelper.getUserId()，绝不信任请求体里的 userId / processBy。
  • 移动端不依赖前端隐藏按钮——PRD 验收 10 要求越权操作由后端直接拒绝。
  • Doris 数据源账号建议只授予 SELECT，从数据库层面杜绝业务侧误写事实表。
  • 企业微信推送凭据（CorpId / Secret / AgentId）加密存储于配置中心，不入库、不进仓库。
  • 关键操作（建任务、改推送规则、触发报告、提交报告、预警处置）均已接入 @Log 操作日志。
