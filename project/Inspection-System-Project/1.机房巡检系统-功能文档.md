## 1. 项目概述

### 1.1 项目名称
机房巡检系统 (Computer Room Inspection System, CRIS)

### 1.2 项目背景
机房是企业关键基础设施,涉及服务器、空调、消防、安防、UPS、PDU 等大量设备,需按周期对各点位现场巡检。当前以纸质记录为主,存在四大痛点:

- **不到位**:巡检员是否真到现场无法验证,纸质记录可事后补填。
- **效率低**:表单填写、回收、归档耗时,数据无法实时汇总。
- **难追溯**:照片与巡检内容割裂,故障时缺乏现场佐证。
- **难统计**:完成率、异常率依赖人工统计,周期长、误差大。

### 1.3 项目目标
通过 **"一物一码 + 手机拍照 + 后台管理"** 实现:

1. **强制到位**:必须现场扫码才能提交记录,杜绝代签、补填。
2. **过程留痕**:每次巡检必须拍照 + 填写结果。
3. **实时可视**:管理端实时查看巡检情况,支持多维筛选。
4. **快速上线**:基于若依框架,复用成熟的后台管理能力,聚焦巡检业务本身。
5. **可扩展**:支持单公司多机房,后续可对接工单、告警等系统。

### 1.4 项目范围

| 端 | 模块 | 说明 |
|---|---|---|
| **PC管理端** | 机房管理 | 维护机房(名称、位置、负责人),多机房数据隔离 |
| PC管理端 | 点位管理 | 新增/编辑/删除/Excel批量导入点位,生成/导出二维码 |
| PC管理端 | 巡检项模板 | 配置可复用的检查项模板 |
| PC管理端 | 巡检记录 | 查看所有巡检记录、照片,多维筛选、导出 |
| PC管理端 | 统计报表 | 巡检趋势图、点位维度排名 |
| PC管理端 | 异常提醒 | 站内醒目提示(列表红标 + 登录弹窗) |
| **手机H5** | 扫码 | 调起摄像头扫描二维码 |
| 手机H5 | 巡检执行 | 查看点位信息、逐项填写巡检结果 |
| 手机H5 | 拍照上传 | 现场拍照(多张)、压缩后上传至对象存储 |
| 手机H5 | 我的记录 | 查看本人已提交记录 |

## 2. 技术基线(若依框架)

### 2.1 框架选型
系统基于 **若依(RuoYi)** 框架开发,后端 Spring Boot + MyBatis,管理端 Vue + Element UI,手机端使用若依 App 端(uniapp)。

### 2.2 复用清单

| 能力 | 若依内置 | 本系统处理方式 |
|---|---|---|
| 登录认证 | 账号密码 + 图形验证码 | **直接复用**,手机端同样走账号密码 |
| 用户管理 | 用户 CRUD、分配角色 | **直接复用**,巡检员即普通用户 |
| 角色管理 | 角色 + 菜单权限 | **直接复用**,新增"机房管理员""巡检员"角色 |
| 菜单/权限 | `@PreAuthorize` 细粒度控制 | **直接复用**,巡检业务菜单挂载其上 |
| 部门管理 | 树形部门 | **改造为机房维度**,或新增独立"机房"实体 |
| 数据权限 | `@DataScope` 按部门过滤 | **复用思路**,扩展为按机房过滤 |
| 字典管理 | 枚举字典维护 | **直接复用**,巡检结果/周期类型等走字典 |
| 操作日志 | `@Log` 注解自动记录 | **直接复用**,满足"仅关键操作"审计要求 |
| 代码生成 | 单表/树表代码生成器 | **用于加速**,点位/机房等基础表可直接生成 |
| 文件上传 | 本地/云存储可配置 | **扩展为对象存储**,照片走此通道 |

### 2.3 开发效益
- 用户/角色/权限/日志/字典等通用能力无需自研,预计减少大量重复工作。
- 代码生成器可快速产出点位、机房的 CRUD 骨架,开发聚焦巡检业务逻辑与二维码、拍照上传等特色功能。
- 手机端可直接基于若依 App 端脚手架改造,复用登录、请求封装、路由等基础设施。

## 4. 5W1H 分析

### 4.1 Why — 为什么做
- 解决纸质巡检"不到位、效率低、难追溯、难统计"四大痛点。
- 满足合规审计对设备巡检可追溯性的要求。
- 为后续设备健康度分析、预测性维护打基础。

### 4.2 What — 做什么
- **交付物**:PC 管理端 + 手机 H5 + 后端服务,技术栈基于若依。
- **核心闭环**:**新增点位 → 生成二维码 → 手机扫码 → 拍照上传 → 后台查看**。

### 4.3 Who — 谁用
- **巡检员**:一线员工/外包巡检员,手机端日常使用,用户名密码登录。
- **机房管理员**:运维主管,PC 端配置与查看,按机房分权。
- **系统管理员**:负责机房、账号、系统配置。

### 4.4 When — 何时用
- **巡检周期**:点位级配置,支持每日/每周/每月/自定义间隔。
- **使用时段**:班前/班中/班后,机房夜巡为非工作时间。
- **异常响应**:站内提示,管理员登录或刷新列表时可见。

### 4.5 Where — 在哪用
- **PC 端**:办公室/监控室,网络稳定。
- **H5 端**:机房现场,可能弱网(本期不做离线暂存,弱网时提示重试)。
- **二维码张贴位置**:机柜门、UPS 主机、消防控制箱、配电柜等显眼处。
- **多机房**:单公司多个机房,按机房隔离数据,管理员可切换机房。

### 4.6 How — 怎么做
- **登录**:用户名 + 密码(复用若依账号体系),手机端与 PC 端同一套账号。
- **二维码内容**:`https://{host}/h5/scan?p={encrypted_point_id}`,点位 ID 加密防伪造;扫码后 H5 解析并跳转巡检页。
- **拍照**:H5 调用摄像头,单点位最多 5 张,客户端压缩至 ≤ 1MB/张,上传至**对象存储**。
- **GPS 校验**:做成**可配置开关**(全局开关 + 点位级覆盖),默认关闭;开启时仅记录位置信息不做硬拦截。
- **异常处理**:异常项在管理端列表红标置顶 + 登录时弹窗提醒,不做短信/外部推送。

## 6. 业务流程

### 6.1 主流程:点位创建 → 现场巡检 → 后台查看

```
[管理员 PC]
   ├─ 新建机房(可选,首次)
   ├─ 新增点位 / Excel 批量导入
   ├─ 配置巡检周期 + 巡检项 + GPS开关
   ├─ 系统生成点位ID + 加密二维码
   ├─ 导出/打印二维码
   └─ 张贴至机房现场
        │
        ▼
[巡检员 H5]
   ├─ 打开 H5 → 账号密码登录
   ├─ 点击"扫码巡检" → 扫描二维码
   ├─ 解析点位ID → 校验权限/状态
   ├─ 加载点位信息 + 巡检项
   ├─ 逐项填写结果(正常/异常/不适用/数值)
   ├─ 异常项拍照(强制) + 说明
   ├─ 整体备注(可选)
   ├─ 提交 → 照片上传对象存储 + 记录入库
   └─ 提示"巡检完成"
        │
        ▼
[后端服务]
   ├─ 校验记录完整性(必填项/照片)
   ├─ 写入巡检记录 → 关联照片URL
   ├─ 异常项 → 生成待处理提醒
   └─ 返回成功
        │
        ▼
[管理员 PC]
   ├─ 巡检记录列表实时展示(异常红标置顶)
   ├─ 登录弹窗提醒未处理异常
   ├─ 查看详情/照片 → 标记已处理
   └─ 统计报表:趋势图 + 点位排名
```

### 6.2 Excel 批量导入流程

```
[管理员 PC]
   ├─ 点位管理 → 批量导入
   ├─ 下载 Excel 模板
   ├─ 填写点位数据(名称/机房/区域/编码/周期/巡检项)
   ├─ 上传文件
        │
        ▼
[后端服务]
   ├─ 解析 Excel
   ├─ 逐行校验:必填、编码唯一、机房存在、格式合法
   ├─ 返回校验结果(成功N行 / 失败M行 + 失败原因)
        │
        ▼
[管理员 PC]
   ├─ 查看校验结果
   ├─ 确认导入成功行 → 批量创建点位 + 生成二维码
   └─ 下载失败行报告 → 修正后重新上传(仅上传失败行)
```

### 6.3 异常提醒流程

```
异常项提交
   ├─ 后端标记该记录为"异常"
   ├─ 生成待处理异常项(状态:待处理)
        │
        ▼
[管理员 PC]
   ├─ 登录时 → 检测未处理异常数 > 0 → 弹窗提醒
   ├─ 巡检记录列表 → 异常记录红标置顶
   ├─ 进入详情 → 查看异常项 + 照片
   ├─ 填写处理说明 → 标记"已处理"
   └─ 提醒数减 1
```

## 7. 实体状态

### 7.1 巡检记录状态机

```
[待巡检] ──巡检员扫码进入──▶ [巡检中]
   │                              │
   │                              ├─ 全部正常提交──▶ [已完成(正常)]
   │                              ├─ 存在异常提交──▶ [已完成(异常)]
   │                              └─ 周期结束未提交──▶ [已逾期]
   │
   └─ 周期结束未巡检──▶ [已逾期]
```

| 状态 | 编码 | 说明 | 可转入 |
|---|---|---|---|
| 待巡检 | pending | 周期内尚未开始 | 巡检中、已逾期 |
| 巡检中 | in_progress | 已扫码,正在填写 | 已完成(正常/异常)、已逾期 |
| 已完成(正常) | completed_normal | 全部巡检项正常 | 终态 |
| 已完成(异常) | completed_abnormal | 存在异常项 | 终态 |
| 已逾期 | overdue | 周期结束未提交 | 巡检中(补巡) |

> 说明:若采用"周期计划"模式,系统按周期自动生成待巡检任务;若采用"即扫即巡"模式,则扫码时直接创建记录。**默认采用即扫即巡**,是否引入周期计划任务待开发规格阶段确认。

### 7.2 点位状态

| 状态 | 编码 | 说明 | 二维码 |
|---|---|---|---|
| 启用 | active | 正常参与巡检 | 有效 |
| 停用 | inactive | 不参与巡检 | 失效 |
| 维护中 | maintenance | 临时关闭,扫码提示维护说明 | 失效 |

### 7.3 异常项状态

| 状态 | 编码 | 说明 |
|---|---|---|
| 待处理 | pending | 异常已提交,管理员未处理 |
| 已处理 | processed | 管理员已填写处理说明并关闭 |

## 10. 业务实体关系

> 仅描述业务实体与关系,不涉及具体表结构与字段类型(属开发规格阶段)。

```
机房 (Room)  1 ──── N  区域 (Area,可选层级)
机房 (Room)  1 ──── N  点位 (Point)
点位 (Point) 1 ──── N  点位巡检项 (PointItem)  ──引用──▶  巡检项模板 (ItemTemplate)
点位 (Point) 1 ──── N  巡检记录 (InspectionRecord)
巡检记录      1 ──── N  巡检项结果 (RecordItem)
巡检记录      1 ──── N  巡检照片 (Photo)  ──存储在──▶  对象存储
巡检项结果    1 ──── 0..1  异常项 (AbnormalItem)
巡检员 (User) 1 ──── N  巡检记录        (巡检员来源:若依用户表)
```

核心约束:
- 一个点位归属唯一机房。
- 一条巡检记录归属唯一点位与唯一巡检员。
- 巡检项结果逐条对应点位配置的巡检项。
- 只有判定为"异常"的巡检项结果才生成异常项记录。

## 11. 接口契约(摘要)

> 约定业务接口语义,具体出入参在开发规格阶段细化。路径遵循若依风格。

### 11.1 机房管理
- `GET /inspect/room/list` 机房列表(分页 + 条件)
- `POST /inspect/room` 新增机房
- `PUT /inspect/room` 修改机房
- `DELETE /inspect/room/{id}` 删除机房(软删,存在点位时禁止)

### 11.2 点位管理
- `POST /inspect/point` 新增点位,返回点位 ID + 二维码 URL
- `GET /inspect/point/list` 点位列表(按机房/区域/状态筛选)
- `GET /inspect/point/{id}` 点位详情(含巡检项)
- `PUT /inspect/point` 修改点位
- `DELETE /inspect/point/{id}` 软删
- `GET /inspect/point/importTemplate` 下载 Excel 模板
- `POST /inspect/point/importData` 上传 Excel,返回逐行校验结果
- `POST /inspect/point/importConfirm` 确认导入成功行

### 11.3 二维码
- `GET /inspect/point/{id}/qrcode` 单点位二维码(PNG + 加密内容)
- `POST /inspect/point/qrcode/batchExport` 批量打包下载(ZIP)

### 11.4 巡检项模板
- `GET /inspect/itemTemplate/list` / `POST` / `PUT` / `DELETE`

### 11.5 巡检执行(H5)
- `POST /inspect/scan/resolve` 二维码内容 → 点位详情(校验权限/状态)
- `POST /inspect/record/submit` 提交巡检记录(含照片 ID 列表)
- `POST /inspect/record/draft` 保存草稿
- `GET /inspect/record/my` 本人巡检记录
- `POST /inspect/photo/upload` 上传单张照片至对象存储,返回 URL
- `GET /inspect/record/myPointList` 本人所属机房的点位列表(辅助手动输入)

### 11.6 巡检记录(PC)
- `GET /inspect/record/list` 分页查询(机房/点位/巡检员/时间/结果筛选)
- `GET /inspect/record/{id}` 详情(含巡检项结果、照片 URL 列表)
- `GET /inspect/record/export` 导出 Excel
- `PUT /inspect/record/{id}/remark` 追加管理员备注

### 11.7 统计报表
- `GET /inspect/stats/trend` 时间趋势(按日/周/月聚合巡检次数、异常率)
- `GET /inspect/stats/pointRank` 点位维度排名(巡检频次、异常次数)
- `GET /inspect/stats/abnormalCount` 未处理异常数(登录弹窗用)

### 11.8 异常项
- `GET /inspect/abnormal/list` 异常项列表(按状态筛选)
- `PUT /inspect/abnormal/{id}/process` 标记已处理 + 处理说明

## 13. 风险与假设

### 13.1 假设
- A1. 机房具备基础 4G/Wi-Fi 覆盖,弱网时由用户重试(本期不做离线)。
- A2. 巡检员使用 Android/iOS 手机,系统版本主流。
- A3. 巡检员与管理员均使用若依账号密码登录。
- A4. PC 管理端使用主流现代浏览器(Chrome/Edge,兼容若依前端基线)。
- A5. 单机房点位数量级 < 1000,日均巡检记录 < 500 条。
- A6. 已具备可用的对象存储服务(自建 MinIO 或云厂商 OSS/COS)。

### 13.2 风险

| ID | 风险 | 影响 | 缓解措施 |
|---|---|---|---|
| R-001 | 机房弱网导致上传失败,且无离线缓存 | 中 | 自动重试 + 明确失败提示 + 保留草稿 |
| R-002 | 二维码被拍照外传,存在代签风险 | 中 | 二维码加密 + 可选 GPS 记录 + 提交时间戳 |
| R-003 | 照片体积过大,占用对象存储与带宽 | 中 | 客户端压缩 + 服务端二次压缩 + 存储生命周期策略 |
| R-004 | 点位编码允许人工修改,可能重复或不合规 | 中 | 唯一性校验 + 编码格式校验 + 禁用修改后冲突提示 |
| R-005 | 多机房权限边界不清,越权访问 | 中 | 复用若依数据权限,严格按机房过滤 |
| R-006 | Excel 导入数据质量差,批量产生脏数据 | 中 | 逐行校验 + 导入前预览 + 失败行报告 |
| R-007 | 巡检员绕过 H5 直接调接口提交 | 高 | 二维码加密 + 后端二次校验 + 关键操作日志 |
| R-008 | 对象存储不可用导致照片上传失败 | 中 | 上传失败重试 + 降级提示 + 监控告警 |
