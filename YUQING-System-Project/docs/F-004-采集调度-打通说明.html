2. 技术选型

选型原则：不引入离线构建拿不到的重依赖，能用 JDK 21 内置能力就不引第三方；反爬与渲染这类高成本能力做成「可插拔档位」，先打通主链路再逐步升级。

环节选定方案架构文档建议取舍说明
HTTP 下载JDK 21 内置 java.net.http.HttpClientApache HttpClient 5本机离线仓库未声明 HttpClient5 制品；JDK 内置同样具备连接池、HTTP/2、超时与重定向，零新增依赖。HttpFetcher 是 SPI，后续换 curl-impersonate / JA3 指纹方案不动上层。
HTML 解析Jsoup 1.11.3Jsoup 1.17+离线仓库仅有 1.11.3。CSS 选择器 API 已足够（选择器 / 属性 / 文本 / 正则取值），已在 pom.xml 注释中标注「私有仓库可达时建议升到 1.17+」。
动态渲染render 档降级为静态解析PlaywrightPlaywright 需下载浏览器内核，离线不可用。适配器保留 render 类型，当前按静态解析执行并记录降级；接入 Playwright 只需替换该档实现。
任务调度SnailJob 2.0.2（工程已有）SnailJob已有依赖，@JobExecutor(name="yuqingCollectDispatch") 即可挂上；不新增调度组件。
限流 / 去重计数器Redisson 4.6.1（工程已有）Redisson令牌桶 RRateLimiter + 信号量 RSemaphore + SETNX 去重，全部走 RedisUtils；Redis 不可用时自动退回进程内实现，保证单机可跑。
事实表写入Doris Stream Load（HTTP PUT）Stream Load5 秒 / 1000 条批量攒批，label 天然幂等；另备 jdbc（无 Doris 时指向 MySQL）与 noop（只计数）两种出口模式。
原始快照MinIO（OssClient，ObjectProvider 注入）MinIO取不到 OSS Bean 时静默降级，不影响主链路。
JSONJackson 3（tools.jackson）—本工程 Spring Boot 4.1.0，实际使用 Jackson 3，不是 Jackson 2。引擎内统一走自建门面 CollectJson。
环境坑位（已固化进文档）：本项目 pom.xml 的 spring-boot.version=4.1.0，对应 Jackson 3（tools.jackson.databind.*）与 JUnit 6.0.3。写 com.fasterxml.jackson.* 会直接编译失败；且 Jackson 3 移除了 JsonNode.elements()（改用 values()）。

关键机制

机制做法
配置驱动适配站点用 YAML 描述（列表页 URL 模板、列表项选择器 / JSON 路径、12 个字段取值规则、翻页规则、反爬参数）。AdapterRegistry 按 yq_channel.adapter_class 找 spec；entry-type=render 在未接 Playwright 前降级静态解析。
三层去重① 批内 Set<urlHash>；② 跨批 Redis SETNX（TTL 3 天，含失败回滚）；③ Doris Unique Key(collect_date, url_hash) 合并写入。任一层失效都不会造成重复入库。
两处限流令牌桶控「每秒请求数」，信号量控「并发数」；两者取更严者。渠道级 request_interval × concurrency_limit 构成频率下限，与全局 min-interval-seconds 取大。
增量水位线以 yq_channel.last_collect_time 为水位线，早于水位线的记录不入库；整页无新增即终止翻页（既省请求，也能防住忽略 page 参数、每页回同一批的坏接口）。
退避重试指数退避 + 抖动（1s × 2^n，上限 60s，抖动 ±30%）。单单元失败不阻塞整批（fail-fast=false），失败原因归并进日志（截断 1000 字）。
可退化运行Redis / OSS / Doris 任一缺失都不阻塞：限流与去重回退进程内实现，快照静默跳过，落库切 noop/jdbc。这是本次能在离线环境跑通自测的前提。

4. 数据流与接口

4.1 内部服务接口（PRD §6.2）

IYqCollectService —— 采集引擎对系统内部暴露的唯一入口，PRD 明确 F-004 不新增对外业务 REST 接口，调度不经 HTTP 暴露。

方法职责
dispatch()按全部启用任务下发采集批次，返回 DispatchSummary（下发/跳过/失败单元数、耗时）
dispatchTask(Long taskId)按指定任务下发（单任务手动补采）
collectOnce(Long taskId, Long channelId)立即采集「任务 × 渠道」一个单元
saveRaw(CollectUnit, List<RawOpinion>)原始数据落库 + 链接去重（供外部导入 / 复采复用）
overview()采集概览指标（当日 fetched/inserted/dup/failed/batches + 任务运行态）
planUnits(Long taskId)预演：列出将被下发的采集单元及跳过原因（排障用）
validateSchedule(YqTask)频率合规校验，返回不满足渠道限流下限的配置项

4.2 对外 REST 接口（运维用，仅 5 个）

为便于运维与排障，保留极少量只读/触发型接口，全部复用既有菜单权限，不新增菜单与按钮。

定时入口：@JobExecutor(name = "yuqingCollectDispatch")。在 SnailJob 控制台建一个任务、执行器指向该名字即可，建议 cron 每分钟触发（真正的到期判定在服务端按水位线做，多次触发是幂等的）。

4.3 落库与读写边界

库表权限写入方式
Dorisyq_opinion（32 列，分区键 collect_date）只写不改Stream Load JSON 攒批（默认 5s / 1000 条），label 幂等；业务侧对本表只读
Dorisyq_collect_log（15 列）只写不改同上，逐单元一条采集日志（验收标准 10）
MySQLyq_task / yq_channel / yq_task_channel / yq_task_keyword读写读配置；回写 last_collect_time、last_schedule_time（水位线）
跨库铁律：@DS("doris") 会路由整个调用栈，因此 @DS("doris") 方法内不得调用 MySQL Mapper；采集链路上不做跨库 JOIN、不用分布式事务 —— Doris 侧只写事实、MySQL 侧只写配置与水位线。

8. 安全设计

8.1 越权

  • 所有对外端点标 @SaCheckPermission（v6 规范，非 @PreAuthorize）：读用 yuqing:monitor:list、触发用 yuqing:monitor:run、校验用 yuqing:task:query；复用既有菜单权限，不新增菜单行，避免权限面扩散。
  • 触发型接口标 @Log(title="采集调度", businessType=OTHER)，操作可审计。
  • 用户身份不从请求体取；采集任务/渠道 ID 一律作为参数显式传入并做存在性校验，不做「隐式当前用户」推断。
  • Doris 事实表在业务侧只读：采集引擎是唯一写入方，且只通过 Stream Load 写，不给业务接口任何 update/delete 通道。

8.2 本地文件读取（本轮新增加固）

下载器原支持 file: 协议（用于离线自测 / 历史快照复采）。该协议能被用来读取本机任意文件，属真实风险面。

已加固：新增开关 yuqing.collect.allow-local-file，默认 false；关闭时命中 file: 直接抛 IOException 并说明原因。即使攻击者能改写配置，也需显式打开该开关才会形成读取入口。已补安全回归用例 localFileSchemeBlocked（验证「默认拒绝」+「开关生效后放行到读文件阶段」）。

8.3 注入

  • 数据访问全部走 MyBatis-Plus 参数绑定（LambdaQueryWrapper / buildQueryWrapper），无 ${} 拼接；已用静态扫描确认采集包内不存在字符串拼 SQL。
  • Doris 写入走 Stream Load JSON body，label 由 IdWorker 生成，不做 SQL 语句拼接。
  • url_hash 用 SHA-256 归一化（先剔除 utm_* 等追踪参数、再按 key 排序重建 query），既做幂等键也顺带消掉了 URL 里的注入噪声。

8.4 XSS

  • 采集到的 title / content / raw_html 均视为不可信内容，只入库不渲染；H5 / PC 端展示时按既有安全基线做白名单净化（剥 script/style/iframe/object/embed/link/meta/base/form + 全部 on* 事件 + javascript: / vbscript: / data: 协议 + srcdoc / expression()）。
  • 快照保留原始 HTML 是 AC4 的硬要求，因此「原文」与「渲染」在两处彻底分离：快照只落对象存储，不进任何前端渲染路径。

8.5 凭据与配置

  • Doris 写入账号、代理出口账号均为配置项（样例里是占位值），不入库、不进仓库；生产应放配置中心并加密。
  • 代理凭据支持 user:pass@host:port，由 ProxyProvider.credentials() 按 host:port 反查，避免把口令散落在请求对象里。
  • 引擎总开关 enabled 默认 false —— 未配置适配器前不可能误发外部请求，这是防「配错就开扫」的第一道闸。

8.6 合规边界（采集特有）

  • 反爬对抗的定位是「保证正常采集的稳定性」，不是绕过授权：优先 C 档官方 API，其次 A 档静态页；BlockDetector 识别到验证码 / 付费墙时记为拦截并退避，不做验证码破解。
  • 请求频率受双重下限约束（全局 30s + 渠道 request_interval × 并发），默认即低频。
  • 示例站点适配器上线前必须替换并确认采集授权与 robots 策略（PRD §8.4 待确认项 3）。
  • 仅采集公开信息，不触碰登录态 / 个人隐私数据。
